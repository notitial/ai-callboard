# Callboard Panels

Callboard Panels is the VS Code side of **callboard**, the Claude Code mod that lets one session (a *lead*) run other sessions (*lanes*) in the same repo. The mod handles the cues. This extension opens and closes the Claude Code panels the lanes live in, and opens the panel of a new lead for a conductor.

## What it does

- **Opens a lane.** A lead's `lane_open` writes a request under `~/.claude/callboard/open/`. The window whose first folder is that lane's folder opens one Claude Code panel, finds its session id by diffing the session registry (one open at a time) and answers with it. The lead then names it and starts it.
- **Opens a new lead.** A conductor's `lead_open` writes `<NAME>.lead` (one line naming the repo). The window whose first folder is that repo opens a panel the same way and answers on `<NAME>.result`, with the request's nonce.
- **Reopens a parked lane.** For `lane_unpark`, it answers `<LANE>.reopen` (the saved session id, one line) by reopening that exact conversation as a panel, but only when the lane's record names that session id.
- **Reopens a parked lead.** For a conductor's `lead_unpark`, it answers `<NAME>.reopen` the same way when no lane carries the name: the lead's record under `~/.claude/callboard/lead-records/` must name that session id, and the lead's repo must be the window's first folder.
- **Closes finished panels.** Every 2 seconds it checks the panels it opened and closes a panel's tab once that session's registry entry is gone and its process is dead. It closes one matching Claude tab only and never a panel with a reserved name. The conversation history stays.
- **Closes the tab of a stopped lane.** After `lane_retire`, `lane_park` or `lane_terminate` (or a conductor's `lead_park`, `lead_retire` or `lead_terminate`) sent the signal, the lead's mod also writes `~/.claude/callboard/open/<LANE>.close` (session id, pid and lane name, three lines). The window that has the lane folder open adds that panel to the same sweep, so the tab of an attached lane, or one resumed by hand, closes too, under the same rules. Nothing is answered and nothing happens in a terminal. A request is written only when the signal exited 0, and an adopted panel that no registry entry shows within 5 minutes is dropped.

- **Serves the plugin build too.** A second spool, `spool-v2.js`, reads `~/.claude/callboard/v2/open/<id>.req`, one JSON request each: `open` (a folder), `reopen` (a session id and a folder) or `close` (a session id, pid, name and folder), written as `.<id>.tmp` and renamed, with a fresh random id and the folder exactly as VS Code names it. A window that serves the folder takes it (its first folder, or every workspace folder when the Claude Code extension is patched, see below), drops it when it is older than a minute, and answers in `<id>.result` (`{ok:true,sid?}` or `{ok:false,code}`). It reads no lane store and has no rate limits; the plugin caps live children. The first spool above keeps serving the old mod until that one is removed.

It doesn't touch the terminal, any setting or the network. It reads and writes request files under `~/.claude/callboard`, reads `~/.claude/sessions` and the lane store under `~/.claude/callboard/lanes`, and runs `/bin/ps` to check a session's process.

## Requirements

- The **Claude Code** extension (`anthropic.claude-code`). It's declared as a dependency.
- The **callboard mod**, loaded from your checkout of the ai-manager repo. This extension is a link into the same checkout, made once by callboard's `link-extension.py`. It isn't on the Marketplace.

## Things to know

- **One repo per window, unless Claude Code is patched.** Claude Code opens a new panel in the window's *first* folder, so a window answers only for lanes in that folder, and a lane of another folder of a multi-root workspace needs its own window. `tools/callboard/patch-claude.py` (an opt-in script you run yourself, or `/patch-vs-claude` in a session in this repo) gives Claude Code's `claude-vscode.editor.open` a `{cwd}` in its sixth argument and writes `callboard-cwd-patch.json` into the Claude extension's folder. When that marker is there and names the sha256 of the folder's `extension.js`, this extension reads it at window start (Output > Callboard Panels says `claude cwd patch: present` or `absent`), passes the lane's folder as `{cwd}` and answers, in the plugin build's spool (`spool-v2.js`), for every folder of the window's workspace, after checking the folder is one of them; a reopen passes the folder too, which makes the conversation resume there. The old mod's spool keeps answering only for the first folder. With no marker it behaves as before. A patch applied or undone takes effect at the next window reload. A Claude Code update is a new folder, so it starts unpatched until the script runs again. The same patch also adds a style block to the Claude panel's page (a wider composer, an icon-only Remote Control chip); this extension does not read that part. The patch covers the `editor.open` command only: a Claude panel that Claude Code itself restores or reopens (a tab restored at a window reload, Reopen Closed Session) starts in the window's first folder, so a lane of another folder is reopened by callboard (`lane_unpark`) and not by that restore. The patched command also ignores a `cwd` that is not one of the window's folders, and when a fresh panel is opened by a `+ New session` button (a call that carries an options object but no `cwd` or session id) in a window with several folders it opens VS Code's own folder list first and uses the pick; Escape opens nothing. A bare call (the palette's Open in New Tab, Open, an @-mention) never asks and starts in the first folder, because it cannot be told from the internal callers that use the same call.
- **Names the folder of the panel in front.** In a window with more than one folder, a status bar item on the right side of the status bar shows the folder (`$(folder) name`, the full path as its tooltip) of the Claude panel in front. It finds the session by the tab's label in the session registry (Claude Code cuts a label longer than 25 characters to 24 and "…", which it matches too), so it works without the patch, and it hides itself for a tab that is not a Claude panel or a name that no live session, or two sessions in different folders, carry.
- **Lists every lane.** A tree "Callboard Lanes" in the Explorer has one row per callboard session the records know, open or not: the session table the plugin keeps (`~/.claude/callboard/v2/sessions.json`) and the lane stores, joined with the live registry rows. A row shows the lane's name, its folder and its state (live, working, waiting, parked, closed, gone; a session gone for a week drops off); its tooltip shows the lead, the full path and the time of its last activity. A lane sits under the lead that owns it. A click reopens the session in its own folder the way `lane_unpark` does, with the same refusals (without the patch, only the first folder of the window). Below the lanes, each folder of the window that has saved Claude conversations has a group "Recent chats: <folder>" with its newest 15: it reads only the file names and times in `~/.claude/projects/<folder>/`, never a transcript, and names a row by the session's name when a record or a live session has one, else by the first 8 characters of its id; a click opens that conversation in the folder. The list refreshes every 3 seconds.
- **Files its sessions in the sidebar's groups.** Every 10 seconds, when the Claude Code patch's second piece (the command `callboard assign group`) is in, a live session of this window's folders that is a lane, a lead (from the lane stores and lead records), or the conductor of a lead goes into the Session Manager group named Lanes, Lead or Conductor. A missing group is created, a name is matched in any letter case (`LANES` too), and a session that already sits in a group stays there. Each session is handled once (a list in this extension's own state), so one you move out of its group is not put back. Without the patch, or before the window reload that loads it, the command does not exist and this does nothing. The patch is undone by `patch-claude.py --undo`; a patch applied before this piece existed reads `outdated` and `patch-claude.py --update` brings it in (then a window reload).
- **Limits.** At most 6 panels a minute. A lane made by a lead is refused when its repo already has 8 live sessions. A lane that already has a live session is refused.
- **Focus stays put.** A panel it opens doesn't keep focus: the tab you were on comes back.
- **A closed lane is not left unread.** Claude Code marks a session unread, and counts it as active in its session list, when its last turn ended in a tab that was not showing. Before it closes a stopped lane's tab that is hidden, this extension shows that tab for a moment (about a third of a second), then closes it and puts the tab you were on back in front. For that moment the keys you type go to the closing tab, and if you were in a terminal or a side bar, focus ends in the editor tab that was in front. A tab you closed yourself before that keeps its mark: use Mark as read in the session list.

## Updating

The version is fixed, so an update is a pull of the checkout plus a window reload (Developer: Reload Window). Output > Callboard Panels shows the build the window loaded. Only a change to this folder's `package.json` needs a version bump: then quit VS Code (Cmd+Q), pull, run callboard's `link-extension.py --apply` from a plain Terminal, and reopen VS Code.

More in the callboard README in the [ai-manager repo](https://github.com/notitial/ai-manager).
