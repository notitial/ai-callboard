# Callboard Panels

Callboard Panels is the VS Code side of **callboard**, the Claude Code plugin that lets one session (a *lead*) run other sessions (*lanes*) in the same repo. The plugin handles the cues. This extension opens and closes the Claude Code panels the lanes live in.

## What it does

- **Takes the plugin's requests.** The spool, `spool-v2.js`, reads `~/.claude/callboard/v2/open/<id>.req`, one JSON request each: `open` (a folder), `reopen` (a session id and a folder), `close` (a session id, pid, name and folder) or `pick` (a conductor's folder and the repos saved for it), written as `.<id>.tmp` and renamed, with a fresh random id and the folder exactly as VS Code names it. A window that serves the folder takes it (its first folder, or every workspace folder when the Claude Code extension is patched, see below), drops it when it is older than a minute, and answers in `<id>.result` (`{ok:true,sid?}` or `{ok:false,code}`). It has no rate limits; the plugin caps live children.
- **Opens a lane or a lead.** An `open` opens one Claude Code panel in the folder, finds its session id by diffing the session registry (one open at a time) and answers with it. The plugin then names it and starts it.
- **Reopens a parked session.** A `reopen` opens that exact conversation as a panel in the folder.
- **Closes finished panels.** Every 2 seconds it checks the panels it opened and closes a panel's tab once that session's registry entry is gone and its process is dead. It closes one matching Claude tab only, and not while a live session carries the same name. The conversation history stays.
- **Closes the tab of a stopped session.** After the plugin stopped a session it sends a `close` request. The window that has the folder open adds that panel to the same sweep, so the tab of an attached session, or one resumed by hand, closes too, under the same rules. A close is not answered. An adopted panel that no registry entry shows within 5 minutes is dropped.
- **Shows the conductor's tick list.** A `pick` comes when you type `/callboard conductor` with nothing saved for the folder, or `/callboard conductor pick`. The window that holds the folder shows VS Code's own multi-select list (`pick.js`): the repos already saved, ticked; the window's other folders, ticked when nothing is saved; and the git repos beside the conductor's folder, unticked. A sibling counts when it is a direct child of the folder's parent, a real directory (a link is skipped) and holds a `.git` entry. Every row is a real path, and the conductor's own folder is never offered. At most 100 rows are shown and at most 32 may be ticked. Escape, or Enter with nothing ticked, changes nothing, and the list closes itself after 80 seconds. The answer (`{ok:true,folders}`) goes back to the plugin, which checks and saves it. The list runs beside the other requests, so a lane still opens while it is up; a second `pick` in the same window is answered `busy`.

It doesn't touch the terminal, any setting or the network (a command you confirm with the Run button below is the one thing it starts, and that command may use the network). It reads and writes request files under `~/.claude/callboard`, reads `~/.claude/sessions` and the plugin's session table under `~/.claude/callboard/v2`, runs `/bin/ps` to check a session's process, and for a conductor's tick list reads the names in the folder that holds the conductor's folder and whether each holds a `.git` entry.

## Requirements

- The **Claude Code** extension (`anthropic.claude-code`). It's declared as a dependency.
- The **callboard plugin**, loaded from your checkout of the ai-manager repo. This extension is a link into the same checkout, made once by callboard's `link-extension.py`. It isn't on the Marketplace.

## Things to know

- **One repo per window, unless Claude Code is patched.** Claude Code opens a new panel in the window's *first* folder, so a window answers only for lanes in that folder, and a lane of another folder of a multi-root workspace needs its own window. `tools/callboard/patch-claude.py` (an opt-in script you run yourself, or `/patch-vs-claude` in a session in this repo) gives Claude Code's `claude-vscode.editor.open` a `{cwd}` in its sixth argument and writes `callboard-cwd-patch.json` into the Claude extension's folder. When that marker is there and names the sha256 of the folder's `extension.js`, this extension reads it at window start (Output > Callboard Panels says `claude cwd patch: present` or `absent`), passes the lane's folder as `{cwd}` and answers, in its spool (`spool-v2.js`), for every folder of the window's workspace, after checking the folder is one of them; a reopen passes the folder too, which makes the conversation resume there. With no marker it behaves as before. A patch applied or undone takes effect at the next window reload. A Claude Code update is a new folder, so it starts unpatched until the script runs again. The same patch also adds a style block to the Claude panel's page (a wider composer, the context ring); this extension does not read that part. A second, optional part of the patch (the marker's `restore` field; this extension does not read it) makes a Claude panel that Claude Code itself restores or reopens (a tab restored at a window reload, Reopen Closed Session) start in the folder that holds its session's transcript, so it resumes there; where that part is not in, or no transcript is found (a panel that never got a message, a sub-folder or worktree), it starts in the window's first folder, and callboard reopens a lane of another folder itself (`lane_unpark`). The patched command also ignores a `cwd` that is not one of the window's folders, and when a fresh panel is opened by a `+ New session` button (a call that carries an options object but no `cwd` or session id) in a window with several folders it opens VS Code's own folder list first and uses the pick; Escape opens nothing. A bare call (the palette's Open in New Tab, Open, an @-mention) never asks and starts in the first folder, because it cannot be told from the internal callers that use the same call.
- **Archives a lane once it is retired.** When the patch's archive-command piece (`callboard archive sessions`) is in, the same 10-second tick remembers each lane of this window it has seen with a table row and a live process, and archives it, as the sidebar's Archive item does, once it has neither on two ticks in a row. So a lane the extension never saw running is never archived, and neither is a parked lane while its row stays, a live one (its process stays) or the manager. A lead a conductor made is archived the same way, from the Lead group, when it is retired and only then: once its row shows it closed or parked it is forgotten, so it stays listed for you to reopen, also after the plugin drops its row. One that was already closed or parked when it was retired stays listed too. The window has to be open at some time while the row shows the lead closed or parked: a lead closed while no window on its folder ran for the 24 hours (28 days when parked) until its row was dropped is archived, and comes back through Unarchive. A lead you typed yourself and a conductor are never archived. A retired session is first filed in its tier's group, since the archive command takes only a session that sits there, and it is tried again until the command names it as archived. A tick with doubt in its reads (an unparsable or missing session table, a registry read with doubt, a manager that cannot be told) names no one, and the two ticks must both be clean. The plugin drops a row when a lane is retired, 24 hours after a lane died without a retire, and 28 days after a park (when the lane can no longer be unparked), so a lane in the last two cases is archived once its row is dropped. The records of lanes and leads seen are kept in this extension's global state under the window's first folder, so a lane seen running and retired while the window was closed is archived at the next tick. A session id that changes inside one running lane (`/clear`) leaves the old id without a row, and the old conversation is archived after 24 hours. An archived lane comes back through Unarchive in the sidebar.
- **Turns a lane's Remote Control on or off.** A `remote` request in the spool names a session id and on or off; the window calls the Claude Code patch's `callboard remote session` command, which toggles Remote Control of the panel that holds that session, and answers `ok` or its code (`no-channel`, `ambiguous`, `busy`, `failed`, `bad-request`). With no patch (or no remote piece in it) there is no such command and the answer is `patch-missing`. The plugin's lanes send it from their own tick (docs/setup.md).
- **Runs a chat code block on your click.** It registers the command `callboard run block`, which the Claude Code patch's run button (the marker's `run` field, `docs/adr/0014-run-button.md`) calls with a shell block's text and the session's folder. The command always asks first in VS Code's own modal, with the folder's name and the whole command, and runs nothing unless you press Run or Enter (whoever calls it); Cancel and Escape run nothing. The text is checked (up to 8,000 characters, no control character but newline and tab, no invisible or direction-changing character) and the folder must exist and be inside one of the window's folders; in a window with several folders a session whose folder the patch does not know yet is refused. It then runs `$SHELL -lc` there (the shell when it is absolute and listed in `/etc/shells`, else `/bin/zsh`) in its own process group with no stdin, a progress notice with Cancel and a 2-minute limit (SIGTERM, then SIGKILL after 2 seconds), keeps the first and last 12,000 characters of output (the first and last 6,000 of error output; what a background process writes after the run ended is dropped), strips ANSI and control characters, and hands the command, output and exit status back to the panel, which sends them into the chat as your message. When the output looks like it holds a secret (a private key, a common token shape, a Bearer or Basic credential, a password in a URL, a long value after `password`, `token`, `secret` or `api_key`; best effort, not a guarantee) a second modal asks for a masked copy (the default), the output as it is, or nothing. One run at a time; a panel reloaded during a run loses the output. Without the patch nothing calls the command.
- **Files its sessions in the sidebar's groups.** Every 10 seconds, when the Claude Code patch's group-command piece (the command `callboard file session`) is in, a live callboard session of this window's folders goes into the Session Manager group of its tier: Manager for the manager (the oldest running session named in `~/.claude/callboard/manager-name`, its process checked by pid and start time, as the plugin picks it), Conductor for a conductor, Lead for any other lead and Lanes for a lane (from the plugin's session table). A missing group is created, a name is matched in any letter case (`LANES` too), a session in another group is moved, and these four groups are kept first, in that order, with any other group after them. The group each session was filed in is kept in this extension's global state under the window's first folder, where Claude Code keeps the groups themselves, so the record and the groups belong to the same account: a session is filed again only when its tier changes, so one you move by hand stays moved until then. A registry read with doubt in it, a manager-name file that is there but cannot be read, or a session with the manager's name whose process cannot be checked, files nothing that tick. Without the patch, or before the window reload that loads it, the command does not exist and this does nothing. The patch is undone by `patch-claude.py --undo`; an install that lacks this piece reads `outdated`, and `patch-claude.py --update` brings it in (then a window reload).
- **Brings the Claude view back at window start.** Claude Code shows its Session Manager only once it has started, so after a restart VS Code restores the side bar to the Explorer. At every window start and reload this extension waits for Claude Code to start, switches the side bar to the Session Manager (opening the side bar if it was closed) and puts the keyboard focus back in the editor, then does the same once more 2 seconds later: if you have clicked into a terminal or another side bar view by then, the side bar switches again and the focus moves to the editor. It runs in every window, with or without a callboard session. There is no setting for it.
- **Focus stays put.** A panel it opens doesn't keep focus: the tab you were on comes back.
- **A closed lane is not left unread.** Claude Code marks a session unread, and counts it as active in its session list, when its last turn ended in a tab that was not showing. Before it closes a stopped lane's tab that is hidden, this extension shows that tab for a moment (about a third of a second), then closes it and puts the tab you were on back in front. For that moment the keys you type go to the closing tab, and if you were in a terminal or a side bar, focus ends in the editor tab that was in front. A tab you closed yourself before that keeps its mark: use Mark as read in the session list.

## Updating

The version is fixed, so an update is a fast-forward of the checkout plus a window reload (Developer: Reload Window). Output > Callboard Panels shows the build the window loaded. Only a change to this folder's `package.json` needs a version bump: then quit VS Code (Cmd+Q), fast-forward the checkout, run callboard's `link-extension.py --apply` from a plain Terminal, and reopen VS Code.

More in the callboard README in the [ai-manager repo](https://github.com/notitial/ai-manager).
